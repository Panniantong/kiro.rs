全账号代理门禁与代理池可观测性

行为：门禁开启后，所有新导入账号（FREE/POWER/PRO/PRO MAX、所有认证方式）必须绑定并验证代理才能启用；代理不足时进入等待队列，绝不回退直连。

迁移边界

只强制新导入账号和后续人工启用账号。历史上已启用且无代理的账号不在部署时批量禁用，避免 8992/8993 突然大面积停服；UI 显示“历史未绑定”，后续按容量逐步迁移。

分配与释放

  • 新账号不再按订阅等级筛选；门禁开启即进入代理分配流程。
  • 无空位：保存为禁用并进入 pending；新增空位后自动补位、测试出口、启用。
  • 代理验证失败：释放槽位，保留 pending。
  • 已绑定账号禁用、额度耗尽或稳定失效：释放代理并触发补位。
  • 既有 PRO+/PRO MAX 的 50 额度退役规则保持不变。

代理池指标

  • 代理总数、每代理账号数、总容量、已用槽位、空闲槽位。
  • 空代理、部分占用、满载代理数量。
  • 占用账号健康：正常（启用且缓存余额>0）、异常（禁用或余额耗尽）、未知（无余额缓存）。
  • 等待账号数和空置原因：无待分配、池满、出口验证失败/账号不可用。

UI

“PRO+ 账号级代理门禁”改为“全账号代理门禁”。新增代理池状态卡，显示容量条、健康/异常/未知分布、空置与等待说明，并提供按代理展开的绑定账号明细。

兼容性

为减少生产迁移风险，运行时继续读取现有配置键和 Admin API 路径；对外文案及实际行为改为全账号语义。本次不迁移 config 文件键名。

验证

  • 测试 FREE/POWER/PRO MAX 新导入均分配代理；池满进入 pending；新增代理后补位。
  • 测试禁用绑定账号释放槽位，50 额度规则不回归。
  • 浏览器验证代理指标与绑定账号健康明细。
  • 8992 灰度后再部署 8993，保留回滚容器。
风险：8993 当前代理容量较小。未来新账号会等待而不是直连，这是预期安全行为；历史无代理账号暂不批量下线。
