Kiro Admin 手动代理管理

设计日期：2026-08-28；基线：全账号代理分支 2298ae4；目标端口：8992 / 8993。

设计决策：在代理池视角提供手动绑定与解除占用。绑定必须容量检查和出口验证；解绑不删除账号/代理，启用账号解绑后自动进入等待或禁用，绝不直连。

手动绑定

  • 代理池展开项提供“手动绑定账号”。
  • 候选账号为存在、未绑定该代理且未超过容量的账号；支持多选。
  • 先以锁保护容量，再写入账号代理；逐个验证出口 IP 与代理 IP。
  • 全部目标绑定成功后，账号按现有全账号门禁启用；任何验证失败的账号释放绑定并保持禁用。

解除占用

  • 每个绑定账号提供“解除占用”。
  • 只清除凭据级 proxyUrl/username/password，不删除账号或代理。
  • 启用账号解绑后立即禁用并进入 pending 队列；禁用账号直接清除绑定。
  • 操作完成后触发等待队列补位。

API

新增代理池视角接口：POST /proxy-pool/bind（proxyUrl + credentialIds）和 POST /proxy-pool/unbind（credentialIds）。复用现有容量检查、持久化和出口验证逻辑；代理密码不从 GET 响应返回。

UI

代理池卡片按代理展开。每个绑定账号旁显示邮箱/ID、订阅、备注、余额和健康状态；提供“解除占用”。每个代理提供“绑定账号”按钮和可搜索多选列表。操作期间禁用重复提交，成功后刷新账号及代理池查询。

验证

  • 绑定 1 个账号成功，超容量被拒绝。
  • 错误代理出口绑定失败并自动回滚。
  • 解绑启用账号后不直连、状态进入等待/禁用。
  • 绑定/解绑数据持久化，重启后关系一致。
  • 后端全量测试、前端构建、8992/8993 health 与 Admin API 200。
风险边界：手动绑定是生产状态变更，但不会改变账号密钥、订阅或代理池认证信息；每次操作均可逆并保留服务端持久化状态。
